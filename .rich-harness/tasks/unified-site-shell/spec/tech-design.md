## 背景和目标

### 需求背景

用户在本会话 2026-10-28 的要求作为来源：R-1，英语启蒙与宝宝技能树是一个网站的平级部分，框架交互共用，仅内容和主题不同；R-2，随时切换任意部分，未来增加其他全科启蒙分类；R-3，移动端和窄屏重视阅读效率与清晰，不能全部平铺；R-4，全局 Agent 与设计原则保存在 Git 项目目录，迁移后可继续维护。此前确认的相对路径、个人数据边界与来源可追溯要求记为 R-5。后续用户在成长会话明确要求全站共用昵称/生日，并以 `2024-11-24` 固定生日自动沿用对应旧资料，记为 R-6；该授权覆盖此前的空默认生日要求。

### 需求理解与澄清结论

当前仓库为原生静态多页面，已有 `home.html`、根成长页和英语页，`site.css` 仅负责互跳链接和首页。成长 `app.mjs` 与英语 `english/app.js` 分别实现目录、弹层和重绘；移动目录断点分别为 `760px`、`900px`。英语构建还生成普通页、离线单文件和公开包。只统一颜色、补链接或追加媒体查询，不能满足共用交互与新增分类的要求。

推荐保留静态多页面，用一个共享运行时和分类注册表承载站点框架。另一可行方案是全量改为单页应用，但会同时迁移两套状态/事件和离线构建，增加数据与旧地址回归风险，本次不采用。框架无新增后端、登录或 RPC 需求。后续用户经成长会话明确要求共用昵称/生日，因此由独立 `shared/baby-profile.js` 服务使用 IndexedDB `xiaoya-site` 提供基础档案，不由导航框架拥有。

## 总体设计

### 页面架构

| 页面 | 保留路径 | 类型 | 接入方式 |
| --- | --- | --- | --- |
| 全站首页 | `home.html` | 修改 | 注册表生成分类卡片，挂载共享站点栏 |
| 成长技能树 | `index.html` | 修改 | 共享框架容器包裹现有领域视图 |
| 英语启蒙 | `english/index.html` | 生成 | 构建内联共享框架，包裹既有五类视图 |
| 英语单文件 | `output/web/英语启蒙路线导航.html` | 生成 | 内联同一实现和资料，使用显式相对根路径 |

依赖关系：分类注册表与框架样式 → 共享运行时 → 首页/成长接入层/英语接入层 → 各自领域内容。共享运行时不得 import 成长存储、英语素材模型或读取个人数据。不新增远程接口。

### 状态管理设计

共享基础档案按后续明确要求由独立服务统一读写；领域记录、词汇与收藏继续独立。全局框架只保留当前分类、当前目录项、目录/分类选择器是否打开、打开前焦点及窄屏模式。分类通过快照传入当前目录和标题，通过回调处理选择；业务状态继续留在成长 state 和英语 S 中。

跨分类使用真实相对链接，完整文档导航；同分类内继续使用现有事件处理和英语 hash。临时展开、筛选与滚动不写入公共档案；普通重绘延续现有状态，不重建整个框架。

## 详细设计

### 目标与设计映射

| Goal / AC | 设计落点 | 关键决策 |
| --- | --- | --- |
| G-1 / AC-1,AC-4 | `shared/site-shell.js`、`site.css`、两端接入 | 站点栏、目录、快捷栏只实现一次 |
| G-2 / AC-2,AC-3 | `shared/site-sections.json`、弹层头 | 单一注册、相对链接、任意层可切换 |
| G-3 / AC-5,AC-6 | 共用基础样式、成长/英语阅读接入 | 摘要优先，完整信息可展开 |
| G-4 / AC-7 | AGENTS.md、docs/architecture.md | 文档随 Git 跟踪，明确实现状态 |
| G-5 / AC-8,AC-9 | 两领域存储与构建脚本 | 不改存储语义和旧入口 |

### 注册与路径

新增 `shared/site-sections.json`，字段为 `id`、`title`、`entry`、`theme`、`icon`、`description`。entry 为相对站点根的路径，允许保留 hash。home 单独作为站点首页入口，不混入当前分类业务菜单。ID 不随标题改名。

构建把 JSON 转成内联公开配置 `window.XIAOYA_SITE_SECTIONS`；不要求页面额外请求 JSON。成长与首页构建/开发入口也由同一注册表生成配置文件 `shared/site-config.js`，该文件标记自动生成且由构建检查一致性。不得手维护第二份注册数据。

运行时以 `siteRoot` 明确指定根相对路径。`resolveEntry(entry, siteRoot)` 保持相对路径，解析时保留 query/hash；注册表是仓库可信配置，不对主题或业务内容加额外拦截。测试覆盖根、英语子目录、导出目录及带 GitHub 仓库前缀的部署位置。

### 框架接口

`shared/site-shell.js` 为无第三方依赖的普通脚本，以 `window.XiaoyaSite` 暴露；支持 Node 导入用于纯函数测试，但浏览器不需要 bundler。

| 接口 | 输入/返回 | 责任 |
| --- | --- | --- |
| `createShell(options)` | 输入 `sectionId`、`siteRoot`、`navigation`、`activeId`、`title`、`onNavigate`；返回控制器 | 创建站点栏、侧栏、主内容槽及快捷栏 |
| `controller.element` | DOM 根节点 | 两分类将其一次性挂载到 app |
| `controller.content` | 主内容 DOM 槽 | 接入层更新领域正文，不负责导航 DOM |
| `controller.actions` | 页级动作 DOM 槽 | 接入层放搜索、保存状态、资料及备份等控件 |
| `controller.update(snapshot)` | 最新目录、选中项、标题、状态说明 | 更新框架，不销毁正文、表单与焦点 |
| `controller.createSectionSwitch()` | 返回独立按钮节点 | 放在详情/预览标题栏，使用同一分类选择器 |
| `controller.openDirectory()` / `closeNavigation()` | 无 | 打开完整目录或关闭框架导航 |
| `controller.destroy()` | 无 | 清除框架创建的监听、弹层和滚动锁 |

navigation 是分组数组，每组含 ID、标题与 items；item 含 `id`、`label`、`icon`、可选 `description`、`shortcut` 布尔值。业务选择只调用 `onNavigate(id)`，交给所属分类映射到原有 view/route/stage/profile 动作。框架不触发两分类已有的 `data-action`，使用独立 `data-site-action` 避免 document 事件代理串扰。

正文可以继续用各自安全 DOM builder 创建，不改成 HTML 字符串拼接。图标使用共享导航图标表，领域图表保留原图标。首页仅挂载站点栏和分类卡片，不显示空局部目录及快捷栏。

### 导航、弹层与主题

按用户后续确认的包含关系分成两层：上方粘性全站栏只放小芽首页和注册表生成的分类链接；下方分类容器承载分类工具栏、局部目录和正文。分类工具栏显示当前分类、局部标题、目录开关及业务动作槽，不能将领域动作挂在全站栏。窄屏仅固定全站栏，分类工具栏随正文滚动；底部保留当前分类快捷入口，避免两层固定导航挤占阅读区域。保存失败/待保存提示保留。

底部快捷栏由最多五项 `shortcut` 生成。成长为宝宝视角/技能全景/下一步，英语为现有五项；不为凑同样数量增减业务视图。`900px` 为框架唯一区分断点；统一 `matchMedia` 与 CSS。图表原有 `760px` 逻辑只负责图，不继续管理导航。

统一原生导航 dialog，分分类选择与完整目录两种内容模式；完整目录只列当前分类分组，分类选择器提供全站分类。只允许一个框架 dialog；重复点开只聚焦已有面板。关闭按钮/遮罩/Escape/选择局部项均走同一清理函数；只有直接点击遮罩才关闭。关闭恢复原触发按钮，触发节点不存在时回到分类工具栏目录按钮。

成长详情 `showDialog` 和英语 `detailShell`、`renderPreview` 增加共享分类按钮。打开分类选择器不会关闭业务弹层或重置输入，原生 dialog 在其上方显示。选择其他分类直接跟随链接，原有 beforeunload 保存保护保留；浏览器阻止离开时原领域表单仍在。选择当前分类只关闭导航，不刷新页面。Esc 优先关闭最上层框架导航，领域快捷键在框架导航打开时不再处理。

CSS 以 `site-` 前缀和变量限定作用域，避免与两端 `.sidebar`、`.topbar`、`.nav` 旧样式碰撞。新容器替换旧框架 DOM 后删去不再使用的框架规则，不靠持续追加高优先级覆盖。共享变量包括 `--site-accent`、`--site-accent-soft`、`--site-surface`、`--site-text`、`--site-muted`、`--site-border` 以及字体、间距、侧栏宽度、层级和安全区。成长与英语主题分别覆盖颜色；不得按主题分叉导航断点与交互。

### 生命周期与状态保存

每个页面创建一次 shell。成长 `render()` 和英语 `render()` 只更新领域正文、动作槽和框架快照，保留输入焦点/选择区、滚动及领域局部状态。完整重挂载前先 destroy，防止媒体监听和导航事件重复。

框架目录中的局部选择关闭抽屉后交给领域导航并更新选中态；分类切换不先调用 reset、清空记录或改写 URL。所有已存在保存队列与错误提示保留；全站框架不新增“自动保存成功”的判断。成长图谱、英语阅读折叠和分批数量沿用各自生命周期。

原生模态负责背景焦点隔离，框架不另设与领域互相竞争的全页 inert。滚动锁仅回收自己设置的样式，不覆盖业务弹层仍需要的锁；恢复宽屏只关闭框架目录，不关闭正在编辑的领域详情。

### 移动阅读

两端统一采用摘要、当前选择与主动作优先。共享基础提供阅读折叠和工具栏样式，领域决定分组与初始展开内容，避免把业务结构交给框架猜测。

英语保留本轮此前已有的单阶段对照、系列路线分组、18项分批、SSS分类、图谱列表替代及原图收纳；将共用字号/间距/触控/目录迁入框架，避免退回全部平铺。

成长保留当前阶段/领域选择与下一步任务；阶段导航在手机用当前阶段、前后及完整选择替代九阶段平铺。四领域以紧凑选择器聚焦当前领域技能；进度摘要仍可查看全部。技能全景保留局部链路和完整路线阅读，完整大图通过明确入口展开。详情先给技能释义与主要记录动作，方法、观察、参考及长路线分组展开；不能隐藏前置、汇合或已记录内容。

所有区域按长期文档字号、44px触控、安全区和无整页溢出标准实施。软键盘打开时不让底栏覆盖输入，底栏与业务固定控件使用同一层级规则；表单与预览内部滚动可到达最后一项。

### 构建兼容

成长/首页通过共享配置脚本和运行时读取；英语 `build.py` 内联同一配置、运行时和 site.css，维持文件可离线打开。单文件内部导航指向旁边工程的相对根路径；脱离整个工程携带时，英语内容仍可读，其他分类需配套站点文件，不声称都已离线打包。

`scripts/build-pages.mjs` 增加共享运行文件白名单；`scripts/build-site.mjs` 统一生成配置并组装站点。普通英语生成、公开英语包和单文件统一从根注册表派生配置。生成配置必须在独立构建成长或英语时也就绪，不能只靠执行全站构建的顺序。

通用领域模型仍使用空档案占位，共享基础档案服务按 R-6 固定生日；公开构建仅包含该项已授权资料及空词汇默认值，移除本机来源路径，AGENTS/设计文档不进入网页包。现有发布分支和发布副本策略不变。

### 文档与维护、新增分类

根 AGENTS.md 保存架构原则、移动规则、数据边界与维护流程，docs/architecture.md 保存长期职责与路径，本方案保存本次目标和详细接口。README 先标记方案状态，实施完成后说明实际扩展步骤；不依赖本机绝对路径定位关键设计。

新增分类步骤：准备静态内容入口 → 在注册表加入稳定 ID/入口/主题 → 使用 createShell 并提供局部目录与动作 → 加入必要构建文件 → 验证首页及各分类任意层互跳 → 验证手机阅读与数据隔离。既有分类无需修改菜单代码。基础档案已由用户后续明确要求并在成长会话实现，详见长期架构“状态与兼容”；云端仍需单独需求。

## 校验规则

| 校验项 | 处理 |
| --- | --- |
| 注册 ID 重复、入口文件缺失、快捷项超过五项 | 构建/测试明确失败，不发布缺入口的导航 |
| 当前分类不在配置中 | 开发报明确信息，保留正文与首页链接，不能白屏 |
| 源码与生成注册配置不一致 | 重新生成并核对差异，禁止分别手改 |
| 目录关闭后仍有锁或焦点丢失 | 视为交互阻断，修复后才能发布 |
| 主题依赖独立导航实现、关键资料仅桌面可访问 | 视为不满足统一架构/移动验收 |
