# 小芽 · 成长与英语启蒙

一个公开仓库维护两套工具：**成长技能树**与**英语启蒙路线导航**。源码统一在 [jadechoulu/baby-growth-tree](https://github.com/jadechoulu/baby-growth-tree) 的 `main` 分支；同仓库的 `codex/pages` 分支保存生成网页，供 GitHub Pages 发布。

| 工具 | 本地入口 | 在线入口 |
|---|---|---|
| 共同首页 | [home.html](home.html) | [小芽首页](https://jadechoulu.github.io/baby-growth-tree/home.html) |
| 成长技能树 | [index.html](index.html) | [成长花园](https://jadechoulu.github.io/baby-growth-tree/) |
| 英语启蒙 | [english/index.html](english/index.html) | [路线与素材](https://jadechoulu.github.io/baby-growth-tree/english/index.html#routes) |

两边顶部通过内部相对链接互相跳转，保留现有根页面、英语路径、hash 和单文件入口。共同首页不替换成长树的旧网址。两边的宝宝资料、成长记录与英语收藏分别保存，不因切换工具自动合并或清除。

长期维护入口为 [AGENTS.md](AGENTS.md) 和 [站点架构与设计原则](docs/architecture.md)。小芽按一个网站、多个平级分类规划；本次 [共享框架改造方案](.rich-harness/tasks/unified-site-shell/spec/tech-design.md) 已整理，待确认后实施。当前两分类的导航实现尚未统一，文档目标不代表已上线功能。

## 唯一维护与发布入口

- 根目录：成长树源码、数据、测试和可选 Worker；英语源码在 `english/`，详细内容见 [英语说明](english/README.md)。
- `node scripts/build-site.mjs`：复用两个去个人资料的构建，统一输出 `dist/site`（根成长树 + `english/` + `home.html`）。`scripts/build-pages.mjs` 与 `english/build.py --pages` 只生成中间组件包，不单独部署到站点根。
- 只保留公开 [baby-growth-tree](https://github.com/jadechoulu/baby-growth-tree)：在 `main` 修改源码，在 `codex/pages` 发布网页。两个分支属于同一个仓库，不需要私有源码仓。个人资料、完成记录和手记仍存浏览器或独立 JSON 备份，不提交到公开仓库。
- 从本工程运行 `node scripts/publish-site.mjs --target ../baby-growth-tree --push`：检查同仓库的发布分支目录干净且 remote/分支正确，构建、同步显式发布文件、提交并推送到 `codex/pages`。不带 `--push` 时只准备并提交发布副本供检查。命令不会复制源码仓 `.git`、个人备份和工作目录。
- GitHub Actions 的“构建小芽完整站点”只生成统一产物；已移除分别部署两套应用的旧工作流，避免覆盖。发布副本继续使用现有 legacy Pages 分支发布，见 [发布说明](deploy/README.md)。

根据「宝宝技能树_A4_打印版_1.pdf」整理的网页，共 248 个技能点、239 条进阶关系，覆盖 9 个年龄阶段和认知、感知觉、粗大运动、精细动作四个领域。原 PDF 的第 5 页是精细动作横向续页。未补造原图中不存在的语言等领域。

当前代码支持两种记录方式：`cloud-config.json` 的 `apiBase` 为空时，直接使用本机 **IndexedDB** 保存，无需 GitHub 登录；配置云端地址后，可使用保留的 **GitHub 登录 → Cloudflare Worker → GitHub 私有记录仓库** 实现；当前没有部署云端服务，也不保留预建记录仓库，不能将个人记录写入本公开仓库。Pages 地址为 <https://jadechoulu.github.io/baby-growth-tree/>；成长树沿用此地址，英语在同站 `english/`。

## 功能与记录

- 宝宝视角：从当前本机或已登录的云端资料读取生日，按真实日历自动计算月龄、定位当前阶段；支持前后按钮和触屏左右滑动，能够返回当前阶段。公开代码的默认生日为空，可建立资料或导入备份。
- 下一步：四大领域各看一个前置已完成的待完成技能，不按月龄过滤；用颜色提示当前、下一、更后或此前阶段。标记后自动接下一项，可撤销，并与其他视角共用记录。
- 宝宝视角可浏览任意年龄阶段，并直接展示阶段脉络图；四个领域的进度卡片与脉络切换合为一组，点击后同时切换图与技能清单。突出所选阶段技能，保留完整前后链路及汇合分支的前序。点击节点可查看直接前序、后续，或展开逐条完整路线；完成状态与下方清单、技能全景共用。清单筛选不会切断图中关系。
- 点击技能名称，或图中节点的「解释」，可阅读通俗释义、生活例子、陪玩方法和观察要点；概念解释与参考资料可展开，不需要登录。解释按唯一技能 ID 复用，查看不会改动完成标记。
- 技能全景：提供「这项技能的完整脉络」与「整个领域全景」。点击节点追踪全部上游和后续；下方单列直接前序、当前技能和直接后续，还可逐条阅读从原图起点到末端的完整路线。
- 蓝色箭头表示前序，粉色表示后续，紫色卡片表示正在追踪的技能；金色虚线补齐后续汇合节点所需的其他前序。领域全景可按能力分支筛选，仍保留跨分支的前序，不会因筛选断链。
- 画布支持拖动、滚动、缩放、一屏看全、定位当前技能及放大查看；按 `Escape` 退出放大画布。宝宝视角和技能详情均提供「脉络」入口。
- 本机记录载入后即可编辑；云端模式需先登录并读取记录。点技能旁的圆圈标记完成，再点一次回退；技能详情可改完成日期和自动保存成长手记。图中节点、完整路线、年龄列表和详情共用状态。
- 每个月龄列和阶段列表顶部提供「全部完成」，一次标记该阶段四个领域的全部技能；已有完成日期和手记保留，可撤销本次新增标记。整阶段完成后显示「✓ 本阶段已完成」，与「宝宝在这里」并列；回退任意技能后自动取消阶段勾选。搜索、领域筛选不缩小批量操作范围。
- 记录以唯一技能 `id` 为键，跨视角、跨阶段共用。跨年龄段「过家家、职业工具」只存一个技能和一份记录。
- 右上角「备份」支持逐份「预览迁入」、「本地全部导入」及 JSON 导入导出。JSON 支持多文件选择；先校验、去重和预览，再确认合并。相同技能采用导入完成状态，未提供的手记及未导入技能保留。
- 本地模式将宝宝资料、完成标记、日期和手记写入 **IndexedDB**，打开页面自动读取，刷新后恢复。旧版 `localStorage` 记录可从备份面板导入；少量查看偏好仍使用 `localStorage`。
- 本地模式显示「正在保存到本机 / 已保存到本机 / 尚未保存到本机」；云端模式以 **GitHub 私有仓库**为主存储，只有服务端确认且本页没有待保存修改时，才显示「已同步」。失败可重试或导出本页记录；仍有未保存修改时，离开页面会请求浏览器提醒。
- 原始 PDF 可从右上角「原始图谱」打开。年龄和进阶关系用于陪伴参考，不将进度作为诊断或评测结果。

原图 `31–36个月` 与 `3–6岁` 在 36 个月交叠。网页保留原文标签，自动定位时从满 36 个月开始进入 `3–6岁`；所有阶段仍可手动浏览。3–6 岁延伸节点保留原图内容。

## 本机保存与可选云端同步

`apiBase` 为空时，页面会自动读取同一来源下的 `xiaoya-growth` IndexedDB 数据库，包括此前保存的记录；无需 GitHub 登录，也无需先迁入已有 IndexedDB 内容。首次使用可建立宝宝资料或导入 JSON。完成、回退、资料、日期与手记都持久保存到该数据库；手记停止输入约 1 秒后保存，成功后显示「已保存到本机」。本地保存不表示已经上传 GitHub，也不提供多设备同步。

本机记录按浏览器和网页来源（协议、域名、端口）隔离；换设备、浏览器或来源时，用 JSON 导出再导入。清除网站数据也会移除本机记录，需保留独立备份。保存失败时仍保留本页修改，可重试或导出后再离开。数据库无法读取时会明确报错，不用空记录覆盖已有数据。

以下身份及云端同步规则仅适用于配置了非空 `apiBase` 的模式。

云端模式未登录时可浏览公开工具外壳、技能目录和原始图谱，不能读取或修改个人记录。Worker 仅允许配置的 GitHub 数字身份访问同一份私有记录；部署时需明确配置本人 GitHub 数字 ID，不是任意 GitHub 用户登录都能访问。

打开页面后，当前标签页有有效会话时会先校验身份、读取云端；没有会话则先登录。读取失败不会用空默认记录覆盖云端。云端尚无记录时，由本人建立资料或确认迁入，页面不会自动初始化个人记录。换设备或清除浏览器数据后，重新登录即可恢复**已同步**的云端记录。

完成、回退、资料和日期修改会进入保存队列；手记在停止输入约 1 秒后合并提交，避免每个字符都生成 GitHub 提交。请求串行处理，网络等待期间继续输入的内容会保留，并在确认版本上继续合并。页面重新获得焦点时，会在没有待同步修改的情况下重新读取云端。

多设备保存使用 GitHub 文件 SHA 版本检查，并按资料字段、技能的完成日期和手记进行三方合并。不同字段可自动合并；同一字段发生冲突时保留双方内容，要求本人选择后再同步，不用最新版本号直接覆盖另一设备。

网络失败、会话失效或冲突未处理时，当前修改暂留本页，不会被标为已同步，也不会改写到 IndexedDB 冒充云端成功。可重试、重新登录，或先「导出本页成长记录」保留包括未同步修改在内的 JSON；关闭或刷新前请完成其中一步，浏览器离开提醒本身不保证保存。

云端模式中，IndexedDB 和旧 `localStorage` 成长记录仅作为迁移来源，不接收日常保存。浏览器的 `sessionStorage` 仅保存当前标签页的 Worker 登录会话；两种模式均使用 `localStorage` 的 `xiaoya-growth-view-v1` 保存视角、年龄阶段、领域和脉络焦点。GitHub Token、OAuth client secret 均只放服务端秘密配置，不能写入前端或公开仓库。GitHub 私有仓库会保留提交历史，删除当前记录文件不等于删除历史资料。

## 从旧本机记录迁入

1. 升级或换地址前，先从旧页面导出 JSON，并保留原文件。本地模式自动载入同来源的 IndexedDB；旧 `xiaoya-growth-v1` localStorage 内容不会自动覆盖当前记录，也不会被删除。
2. 打开「备份」，可对发现的记录逐份「预览迁入」，或点「本地全部导入」汇总此浏览器检测到的全部有效记录。换来源或设备时使用「导入 JSON 备份」，支持一次选择多份文件。云端模式仍需本人登录并成功读取云端后才能导入。原有 v1 备份格式继续兼容。
3. 批量导入要求所有来源的宝宝昵称和出生日期一致，不一致时停止并提示分别预览。重复技能只计算一次；完成日期或手记有差异时，优先采用预览中前列来源的非空值，并列出差异供核对。后列来源可补齐缺失字段，不会按文件修改时间自动判断新旧。
4. 核对来源、宝宝资料、合并后的完成数量、手记和差异。确认后资料更新为导入宝宝；相同技能采用导入完成状态（可能包含回退），未提供的手记和未导入技能保留。单份导入同样适用这一规则。
5. 本地模式等待「已保存到本机」，云端模式等待「已同步」，刷新或重新读取后核对。本地确认会更新当前 IndexedDB 为合并结果；旧 localStorage 和原始 JSON 文件保持原样。格式损坏的旧记录可先导出原文修复，不参与全部导入。

后续可从语雀提供固定 Pages 地址的链接入口。直接上传 HTML 或嵌入的脚本、弹窗和沙箱权限仍需单独验证，语雀账号不会自动变成这份记录的同步身份。

## 内容扩展

`data/catalog.json` 保存技能目录与原图关系。保持已有 `id` 不变，即可在更新内容时复用已保存记录。每个技能结构：

```json
{
  "id": "fine-roleplay-tools",
  "domain": "fine",
  "category": "使用工具",
  "stage": "s4",
  "endStage": "s7",
  "title": "过家家、职业工具",
  "parents": [],
  "sourcePage": 5,
  "guidance": "可选的陪伴说明",
  "enrichment": ["可选的启蒙活动"],
  "toyIdeas": ["可选的玩具候选"]
}
```

`endStage` 仅在技能横跨多个阶段时填写。`parents` 是原图箭头的直接上游，不会因前序技能未标注而锁定后续节点。`domain` 为 `cognition` / `sensory` / `gross` / `fine`；`stage` 为 `s0` 至 `s8`，与年龄阶段顺序对应。

`data/stage-resources.json` 为年龄段扩展内容，以阶段 ID 为键，同样支持 `guidance`、`enrichment`、`toyIdeas`。例如为 `s5` 填入：

```json
{
  "s5": {
    "guidance": "这一阶段的陪伴说明",
    "enrichment": ["活动候选"],
    "toyIdeas": ["玩具候选"]
  }
}
```

有内容时自动显示「陪伴与探索」，空字段不会显示占位区域。技能与阶段还可以增加其他字段，并在对应渲染函数中扩展展示。应用状态、技能目录和阶段补充内容分开保存，内容更新不会覆盖宝宝记录。

`data/skill-guides.json` 保存技能解释，不写入个人记录。`skills` 以技能 ID 为键，包含 `meaning`（通俗释义）、`example`（日常例子）、`play`（陪玩方法）、`observe`（观察要点）、`note`（必要说明）及 `sources`（来源 ID）；`categories` 解释能力分支概念，`sources` 集中保存资料标题、发布机构和原文链接。新增技能时同步补充解释与出处即可。资料用于解释相关能力和活动，不能将原图月龄和自创名称视为参考机构的统一结论。

`lib/model.mjs` 负责月龄、阶段、范围技能、完成状态和备份校验；`lib/graph.mjs` 负责前后依赖、完整路线、跨分支前序和图布局；`lib/storage.mjs` 负责 IndexedDB 读写、旧记录读取及本地保存队列适配；`lib/import.mjs` 负责批量导入去重、资料一致性检查及保留已有手记的合并；`lib/cloud.mjs` 负责云端请求与三方合并；`lib/save-queue.mjs` 负责手记防抖、串行提交及在途编辑保留；`app.mjs` 负责视图、记录模式、登录、明确迁移与备份。`worker/` 负责 OAuth、身份授权、会话和私有仓库读写。
