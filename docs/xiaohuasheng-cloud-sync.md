## 共用链路

`shared/site-sync.js`复用原短期本人会话；`worker/index.mjs`对固定API同时校验来源和本人身份，拒绝客户端传入账号或URL。`POST /api/xiaohuasheng/sync`启动或复用任务，`GET`查询进度与完整结果；`POST /api/xiaohuasheng/backup`在导入前保存合法英语快照。

`backend/netlify/functions/xiaohuasheng-background.mjs`以Netlify的`-background`约定执行最长15分钟任务，避免首次补齐整架目录超过普通请求时间。后台入口仅凭一次性256位随机能力执行，强一致ETag条件消费拒绝重放；未完成任务按本人去重。页面关闭不会主动删除后台任务，再次同步可继续查询；超时或授权失效明确提示，保留旧进度。

`backend/xiaohuasheng.mjs`使用与已验证本机CLI相同的官方固定路由、动态签名、token续取和响应解码。网络URL保留双斜线，签名使用单斜线路径。书架连续分页、双身份唯一性、合法短末页、读过字段及套装完整数量均须通过；目录按4并发读取。详情只派生公开书目字段，图片保留原站链接。缓存只保存元信息，已读及次数每次重新取得；套装已读不投影成员。

完整派生快照仍交给`EnglishShelfLibrary.apply()`、`EnglishBookProgress`和原有保存函数，图鉴、两进度页、廖彩杏、其他继续引用同一单册事实。导入前检查账号、时点、备份及并发编辑，保存后等待私人同步回执；原手工记录、时间、阶段状态和未知字段保持原义。

## 云端授权与保存边界

首次启用需要用户明确允许：把此前仅保存在Mac钥匙串的小花生App授权和签名参数，交由已有的`xiaoya-jadechoulu-sync` Netlify站点保管，用于本人只读书架及目录查询。不另建站点、用户或账号权限。许可前不读取导出、上传或配置真实秘密。

服务端生产秘密变量`XIAOHUASHENG_CREDENTIALS`为JSON，字段为`userId`、`authorization`、`seed`及原会话`version/platform/userAgent/timezone`。不在此文件或示例中填真实值；参数只由已授权工具从钥匙串直接送入平台秘密配置，不经聊天、网页、Git、CI、明文文件或命令参数。API token按官方已验证旧HTTP:83流程续取，仅留后台内存，不把它当永久登录；此原站协议仍无TLS，书架与目录数据请求均为HTTPS，不探测替代登录协议。原登录授权失效后重新登录尚未实现。

`xiaoya-xhs-private-v1`为站点级私有Blobs库，与短期OAuth状态库分开：`current/`保存任务状态，`history/`按新任务保存原始书架分页与派生结果，`catalog/collection`保存元信息缓存，`backups/`保存导入前英语副本。它们不进入公开Pages包，也不替代`records/english.json`的个人进度主库；凭据仅在秘密环境变量与后台内存，不写入这些数据对象。按2026-11-12本人明确要求新增云端定时任务，见下节。
