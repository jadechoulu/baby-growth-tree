## 2026-11-09：共用单册阅读次数（本地实现）

本机派生快照的已读书目增加非负安全整数`readCount`。已保存手机截图中“2次／3次”与同身份接口原值一致，因此作为App书架徽标次数同步；不能据此补造逐条阅读日志或阅读日期，已读仍用`readedFlag=1`。全书架与套装目录只按单册自己的身份关联，不将套装次数分给成员。

次数保存在已有`reading.external.v1:`事实的`note.readCount/readCountObservedAt`，共用单册模型读取。再次同步更新已存在的已读事实，允许次数变少；相同快照幂等，更早次数不覆盖较新值，缺少次数的旧快照保留已有值。重复外部身份取最大值而非求和，手工勾选不补猜次数，完成本数仍按单册去重。

素材图鉴、路线逐本目录、廖彩杏、其他套系内单册共用紧凑次数角标，超过1才显示；套系封面不聚合单册次数。次数沿原私人英语记录、备份和云端回读，不新增公开目录或同步键。本段不代表已发布或私人云端已接收新次数。

## 当前可重复获取流程

1. 先读App API复用文档，确认本机既有授权和指定执行器；复用动态签名CLI，不读取或输出凭据，不需要连接手机。无本机会话时采用公开采集候选或已有完整快照，不把匿名结果当本人书架。
2. 每次输出到新的私有历史目录，读取本人全书架并校验连续分页、业务码、双身份唯一性及终止条件。错误、缺页、重复身份或达到上限时不完整，CLI退出非零，保留上次完整快照。
3. JSON保留全部原字段及以后新增字段，再按`readedFlag=1`派生已读；不用`readFlag`，不把`readCount`改写为真实打卡次数或日期。快照时间只表示抓取时间。
4. 以App`guid`对照旧网页公开ID，保留App数字ID与版次。只有已获导入授权时才转换为既有完整快照契约并调用公共`applyReadSnapshot()`；由本机适配器转为派生快照，不将App原始JSON直接交给页面，或按标题跨版自动绑定。
5. 保存原值、分页证据、状态差异和历史，个人数据留在私有保存／同步边界，不进公共目录、Git或站点包，不自行创建周期任务。

## 历史网页获取流程（兼容参考）

1. 优先检查专用CLI、MCP或网站导出能力。本次交接未发现可覆盖完整账号书单的专用能力；未来每次按实际可用能力选择，不假定只能用某一种浏览器。
2. 浏览器优先内置浏览器；交接当次内置浏览器未登录，已登录Chrome可用，因此由Chrome完成完整读取。后续使用获准且可验证的登录能力，未登录时由用户自行完成登录，不保存Cookie、密码、验证码或浏览器登录状态。
3. 打开已读分类，确认账号、分类名称及页面标注总数。匿名HTTP仅可作可用性／公开结果检查，须标记匿名；不能因能读到部分书目就认定完整。
4. 从实际页面发现分页链接，逐页访问并确认当前页，不写死113本或5页。提取当前书目列表容器内的 `/book/` 链接，按站点书目URL／`bookId`去除封面与文字双链接重复。不要抓入相关推荐。
5. 优先读取链接的原始`title`；缺失时读取对应书目文字并记录异常，不丢条目、不猜测名称。
6. 校验所有发现页已访问、每页唯一数、跨页唯一数与页面标注总数。总数变化、分页中途失败、登录失效、标题缺失或计数不一致均保留诊断；不覆盖最近完整快照。

交接使用的只读DOM表达式如下；它不是远程JSON API。实现时应以实际页面确认的列表容器代替全页`document`，并补充缺失标题处理：

```javascript
Array.from(new Map(
  Array.from(document.querySelectorAll('a'))
    .filter(e => e.getAttribute('href')?.startsWith('/book/'))
    .map(e => [e.getAttribute('href'), {
      title: e.getAttribute('title'),
      href: e.getAttribute('href')
    }])
).values())
```

## 私有快照与映射

快照、账号配置、外部映射和导入历史均为个人英语数据，与公共素材基础资料分开。建议存入既有私有备份区域下的`external-reading/xiaohuasheng/`；具体持久化与云端结构在实现时接入现有英语保存／备份契约，不新增公开数据源。不得放进`english/data/`、公共封面目录、离线HTML或`dist/site`，也不得提交真实书单作为测试夹具。

| 数据 | 必需字段与语义 |
| --- | --- |
| 快照 | `schemaVersion`、`snapshotId`、`fetchedAt`、私有账号内部ID、`sourceUrl`、`sourceKind: xiaohuasheng_bookcase_read`、`authenticated` |
| 完整性 | `advertisedCount`、`actualUniqueCount`、发现／访问页、每页唯一数、`complete`、异常及抓取方式 |
| 原始书目 | `bookId`、原始`title`、完整书目URL、首次／最近观察时间；不同ID保持独立 |
| 匹配 | 外部`bookId`、项目`resourceId`、出版版本、公共级别／`scopeId`、单册ID、匹配依据、状态与用户确认历史 |
| 导入事实 | 来源账号＋分类＋`bookId`的幂等键、来源快照、匹配版本、处理结果和撤回历史 |

快照时间只是抓取时间，首次观察只是系统第一次见到书目，均不能冒充实际阅读日期。外部分类不提供的阅读次数、完成日期、熟练度、有效时长不得虚构。

## 匹配与进展的公共模型

公共素材目录继续单独维护套系、版本、级别与册数，路线只引用这些范围。外部书目映射到同一公共身份，再由各处投影进展，不在许密杉、庆爸、香蕉妈妈页面分别写匹配规则或复制一套外部记录。

- 先解析单册身份与出版版本。只有唯一且证据充分的映射可自动关联；规范化书名仅辅助匹配，不能独自证明同版、同册。模糊、多版本、缺级别／册号的条目进入待核对队列，用户确认后持久复用。
- 外部不同`bookId`若经核定对应同一项目单册，保留外部原条目，内部按规范单册去重；重复刷新、重复导入、跨路线引用均不得重复累计。
- “已读事实”独立于手工数量记录。导入不改写原手工记录；有完整单册身份时按唯一单册汇总。只有手工总数、无法判断与导入重叠时，不直接相加，暂按两者`max`作为已知数量下界并展示来源构成，后续用户核定身份后再去重计算。
- 已知版本、级别和分项总量才计算对应百分比；无可靠总量只记数量。单册已读不能自动完成整套或路线阶段，更不能推定听懂、掌握、复述达标或晋级。各路线的额外任务要求仍按现有模型判断。
- 收藏／拥有、已读、掌握、主线／辅线是独立维度。路线用途继续沿用公共角色与证据规则，不由导入书单改动。
- 抓取缺失不能清空或回退进度。即使完整新快照出现疑似移除，也只记来源差异、保留历史并进入核对，不直接撤销用户手工记录。用户修正错误映射时只撤回对应导入事实，不覆盖随后手工修改。
